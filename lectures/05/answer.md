## 宿題

- 取り組んだレベル：実装
- やったこと（変更したファイル・設定・処理、または設計した取得方法）：
  - `app/retrieval.py` に `expand_neighbors` と `search_with_neighbors` を足した。ベクトル検索の各ヒットに、同じ資料の前後 N ページの本文と引用情報を付ける。前後ページは `load_pages()` の並びのうち、`document_id` が同じページだけから選ぶ。章はまたぐが、資料はまたがない
  - 同じページは 1 回だけ返す。ヒットしたページが別のヒットの前後ページにも当たる場合は、ヒットとして返す。前後ページには `role: "neighbor"` と、どのヒットの前後かを示す `neighbor_of` を付けた。並びはヒットの順位ごとに、前のページ、ヒット、次のページの順である
  - 付けるページ数は環境変数 `AIE_RAG_NEIGHBORS` で切り替える。既定は 0 で、元の `search()` の結果をそのまま返す。ツールの説明文と `INSTRUCTIONS` は変えていない。比べる条件を、取得する範囲の 1 か所に絞るためである
  - `--trace` は `search_materials` の戻り値を先頭 120 文字しか出さないので、返したページを 1 行ずつ表示するようにした。各行には、ヒットか前後ページかと、ヒットの距離を出す。`app.retrieval` にも `--neighbors` を足した
  - テストは `tests/test_retrieval_neighbors.py` に 21 件書き、先に失敗することを確かめてから実装した。資料の境目、章の境目、重複、順位の順、資料の端、設定値の検査を見ている。全体の 38 件が通る
  - 実装後に別のエージェントにコードを読ませ、指摘のうち 2 点を直した。1 点目は、ページ一覧の読み込みエラーがツールの外に漏れて実行が止まる点である。2 点目は、負のページ数の検査が埋め込み API を呼んだ後になっていた点である

- 気づき・疑問：
